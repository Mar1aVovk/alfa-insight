## О проекте

Наше решение кейса «Новостная аналитика для принятия бизнес-решений». Идея простая: руководитель выбирает свою компанию и роль, приложение показывает новости, которые его реально касаются, а по любой из них можно получить разбор и посмотреть, на какие документы Альфа-Банка этот разбор опирается.

## Что умеет приложение

В базе 85 514 компаний, их можно искать по ID, отрасли и городу. Для выбранной компании приложение знает группу, банковские продукты и финансовые связи с другими юрлицами.

Новости мы берём из RSS Банка России, РБК и Интерфакса, убираем точные дубли и держим резервную копию на случай, если источник недоступен. Отбор идёт по деятельности компании, её группе и роли пользователя, и для каждой новости видно, почему она попала в ленту. Приоритет события это не вероятность, а просто степень близости к бизнесу.

Для разбора используются 9 документов банка: 64 страницы, 174 фрагмента, у каждого фрагмента есть номер страницы. Поиск учитывает дату, поэтому материал 2021 года не выдаётся за нынешнюю позицию банка. На экране новость, вывод модели и позиция банка показаны отдельно, а любой фрагмент можно раскрыть и сверить с оригинальным PDF.

Кроме этого есть уточняющие вопросы, возможность вставить свой текст новости, кнопка обратной связи и калькулятор, который считает, как изменение ставки влияет на процентные расходы. Готовые разборы кэшируются.

## Требования к окружению

- Docker с Compose, если запускаете в контейнере
- либо Node.js 22.13.0 или новее и npm (разработка велась на 22.16.0)
- командный ключ API от организаторов
- доступ в интернет: приложение ходит в API организаторов и в RSS новостных источников
- для пересборки данных из исходников дополнительно Python, PyMuPDF и Tesseract 5 с языками rus и eng (для запуска приложения не нужны)
- аккаунт Cloudflare не нужен

## Как запустить

Ключ API в репозитории не хранится, его нужно вписать в `.env`.

### Docker

```sh
git clone https://github.com/cxmzt2s2w5-eng/alfa-insight.git
cd alfa-insight
cp .env.example .env
# впишите свой LLM_API_KEY в .env
docker compose up --build
```

Дальше открывайте http://localhost:3000. База хранится в именованном томе Docker, так что после перезапуска данные никуда не пропадут. Модели поднимать не надо, приложение ходит в API организаторов. Остановить можно через `docker compose down`, а если нужно удалить и базу, добавьте `-v`.

Сразу предупреждаем: Docker-конфигурацию мы написали, но собрать контейнер не смогли, потому что на машине, где шла разработка, Docker не стоит. Если что-то пойдёт не так, запустите приложение без Docker, как описано ниже.

### Без Docker

```sh
npm ci
cp .env.example .env
# впишите свой LLM_API_KEY в .env
npm run build
npm start
```

Миграции для локальной базы применяются сами при `npm start`, аккаунт Cloudflare не нужен. Если хотите править интерфейс и сразу видеть результат, запускайте `npm run dev`.

## Настройки

Всё лежит в `.env`.

`LLM_API_KEY` это командный ключ. Он используется только на сервере и не попадает ни в браузер, ни в логи.

`LLM_BASE_URL` по умолчанию `https://changellenge.up.railway.app/v1`.

`LLM_MODEL` по умолчанию `qwen/qwen3.6-35b-a3b`. Сервер принимает только модели из разрешённого списка.

Ещё в приложении стоит свой лимит: 80 обращений к LLM в сутки. Он нужен как страховка и не равен бюджету в 500 ₽. Денежное ограничение обеспечивает провайдер, а сколько именно рублей потрачено, мы посчитать не можем, потому что тарифов у нас нет. Счётчик обнуляется в 03:00 по Москве. Если закончился бюджет или ключ неверный, пользователь увидит понятную ошибку без самого ключа.

## Как проверить

Можно пройти по такому сценарию.

1. Войдите как финансовый директор и выберите компанию `U_9250`.
2. В профиле должны быть инженерное строительство, кредитный продукт и группа компаний.
3. Откройте любое событие из подборки и посмотрите, как идёт анализ.
4. Проверьте, что новость, вывод модели и позиция банка с датой показаны отдельно.
5. Раскройте фрагмент документа и сверьте страницу с оригинальным PDF.
6. Спросите «Как это затрагивает группу компаний?».
7. Переключитесь на `U_182712`. Подборка должна сместиться в сторону технологических событий.
8. Вставьте свой текст, например про изменение регулирования или стоимости денег.
9. В калькуляторе укажите плавающий долг 100 млн ₽ и рост ставки на 1 п.п. Должно получиться 1 млн ₽ в год.
10. Повторите тот же разбор. Ответ должен прийти из кэша, без нового вызова LLM.

## Используемые компоненты

- **Интерфейс:** React и Vinext, TypeScript
- **Сервер:** route handlers, отбор новостей, поиск по документам и проверка ответов
- **Хранилище:** Cloudflare D1 (локально SQLite) для кэша, обратной связи и учёта запросов к модели
- **Модель:** LLM по API организаторов, по умолчанию `qwen/qwen3.6-35b-a3b`
- **Источники новостей:** RSS Банка России, РБК и Интерфакса
- **Корпус документов:** 9 документов банка, распознанных OCR, с привязкой фрагментов к страницам
- **Подготовка данных:** Python-скрипты в папке `scripts/`
- **Запуск:** Docker Compose или Node.js

## Как устроено внутри

Профили компаний разбиты на 128 файлов, чтобы серверу не приходилось держать в памяти всю базу сразу.

Разбор события проходит несколько шагов, и пока он идёт, пользователь видит статусы по SSE:

1. Строится план: что надо выяснить для этой компании, роли и события.
2. Загружается профиль компании.
3. Идёт поиск по документам банка с учётом даты. Если найденного мало, поиск расширяется.
4. Модель пишет разбор, при необходимости просит дополнительный поиск.
5. Код проверяет все ссылки на материалы и признаки. Всё, чего нет в корпусе, отбрасывается.
6. Отдельный вызов модели проверяет, подтверждаются ли выводы найденными фрагментами.
7. Результат сохраняется в кэш.

Вторая проверка моделью не гарантирует, что вывод верен. Чтобы оценить настоящее качество, нужны эксперты и набор контрольных кейсов.

## Данные

Исходные CSV и PDF в репозиторий не входят, их можно скачать по ссылкам организаторов: [клиентские таблицы](https://drive.google.com/drive/folders/1Ep8wWoEHTg5Q8kwrLx2j_xFyxGUEVxFq) и [материалы банка](https://drive.google.com/drive/folders/15xZTLF1lZ65p6o5xpNA_fRbxjoV-UlG1).

Обезличенные профили и распознанный корпус уже лежат в `public/data`, поэтому приложение запускается без дополнительной подготовки. Распространять эти данные можно только в рамках разрешений организаторов, а перед публикацией репозитория стоит уточнить условия использования.

Если нужно собрать данные заново из исходников:

```sh
python scripts/prepare-data.py --input /path/to/csv
python scripts/ocr-bank.py --input /path/to/pdf --output /path/to/ocr --tessdata /path/to/tessdata
python scripts/compile-sources.py --ocr /path/to/ocr --manifest /path/to/manifest.json --feeds /path/to/rss
```

Языковой пакет Tesseract в репозитории нет, путь к нему передаётся через `--tessdata`. Manifest это массив объектов вида `{"name": "имя.pdf", "source": "публичная ссылка"}`. RSS-копии лежат в файлах `0.xml`, `1.xml`, `2.xml` и `6.xml`, по источникам из `compile-sources.py`.

Несколько допущений, которые мы сделали при работе с данными:

- Значение `REVENUE_COMPANY=1000` считаем пропуском. Год выручки 2025.
- Переводы самому себе в анализ внешних связей не берём.
- По платежу не видно, какие отношения стоят за ним, а сама выборка не доказывает, что мы видим весь бизнес компании.
- Выручка группы это простая сумма по компаниям, а не консолидированная отчётность.
- Данные ФТС не говорят ни о направлении торговли, ни об объёмах.
- То, что физлицо связано с компанией, ничего не говорит о его должности и полномочиях.
- Если у идентификатора есть пустые повторяющиеся записи, мы показываем предупреждение о качестве данных.
- Предпосылки, которые вводит пользователь, всегда отделены от данных банка.

## API

- `GET /api/bootstrap` отдаёт примеры, аудит базы и каталог документов.
- `GET /api/companies?id=U_9250` возвращает профиль компании.
- `GET /api/companies?q=строительство` ищет по базе.
- `GET /api/feed?company=U_9250&role=cfo` возвращает персональную подборку.
- `POST /api/news` принимает новый текст от пользователя.
- `POST /api/analyze` запускает разбор и отдаёт статусы по SSE. С параметром `?format=json` вернёт обычный JSON, так удобнее проверять вручную.
- `POST /api/feedback` принимает оценку релевантности.

## Безопасность и ограничения

Новости сервер собирает только с заранее заданных HTTPS-адресов RSS. Ссылки, которые вставляет пользователь, он не скачивает. Любой внешний текст помечен в prompt как недоверенные данные, а в интерфейсе показывается как обычный текст, HTML не выполняется.

Банковская авторизация и CRM в демо только имитируются. Это не готовая к production система с разграничением доступа. Для работы с настоящими клиентскими данными понадобятся авторизация на каждый профиль, проверка доступа к группе, разделение данных и политика их хранения.

Поиск по документам сейчас лексический, без векторных представлений.

## Устройство репозитория

- `app/page.tsx` и `app/globals.css` — интерфейс
- `app/api/` — серверные обработчики
- `lib/` — отбор новостей, поиск и проверка ответов

- `public/data` — подготовленные данные
- `docs/` — материалы для README

Перед объединением изменений прогоните:

```sh
npm run typecheck
npm test
npm run build
npm run test:smoke
```

Последняя команда запускается после сборки: она поднимает сервер и проверяет страницу, базу, поиск и валидацию запросов. К модели при этом никто не обращается.
